# Architecture

Library removal pauses and detaches media elements before synchronously removing their source and edit state, then releases desktop proxies and owned downloads. A source's active waveform subprocess is cancelled and awaited before deleting its file. Cleanup errors become transient notices; they do not leave a selected player pointing at removed media. A regression repeatedly removes playing local and URL sources in real Electron and checks that the process stays alive; another injects an IPC cleanup failure and checks reimport. This is lifecycle hardening, not a confirmed diagnosis of the intermittent Windows process exit, which still needs its terminal log.

The renderer is shared by Electron and the web. Core logic has no dependency on React, Electron, the filesystem, or WebAssembly.

```text
src/core       Media assets, edit recipes, formats, probe interpretation, timeline rules, versioned projects, output presets
src/engines    MediaEngine interface adapters: browser worker or desktop bridge
src/hooks      Application state, per-asset undo/redo, theme preference, project relinking
src/components Focused editing and export components
src/styles     Tokens, layout, editing surface, controls

electron       Sandboxed preload, main-process IPC, portable native tool adapter
scripts        Asset preparation, development startup, bundling, package verification
```

## Edit model

A source asset has metadata and an opaque ID. Its recipe records source trim boundaries, removals, an optional ordered clip sequence, clip effect overrides, source-wide overlays/captions, output-time audio tracks and delivery settings. `editClips` translates legacy retained sections into the ordered model; `keptRanges` still supports legacy recipes. Splitting preserves each part’s effects. Reordering changes the output sequence while source-anchored elements follow the corresponding footage.

`buildExportArgs` validates the recipe and returns an argument array. Single-range output uses accurate FFmpeg seeking/re-encoding. Multiple retained sections use trim/atrim, timestamp resets, and concat. Both engines execute exactly this plan. Embedded artwork uses a separate unseeked input so trimming audio does not discard the single image packet.

The application owns the media library and bounded per-asset undo/redo histories. The interface sends edit patches rather than constructing FFmpeg commands. Exports use a snapshot of the selected recipe. Imports and exports are serialized by application state, and exports can be cancelled.

## Workspace presentation

`EditorWorkspace` and `ConversionLayout` own panel geometry independently of media recipes. `panel-layout` validates saved sizes and bounds them against available space, reserving a minimum preview area. `useElementSize` observes the actual workspace dimensions; adaptive layouts preserve preferred sizes when temporarily constrained. `usePanelSizes` stores only device-local presentation preferences. `PanelDivider` provides pointer capture, cancellation, keyboard adjustment, and accessible separator values. Panels scroll internally instead of expanding their neighbours; timeline tracks share one scroll viewport, with source-relative zoom and playhead following. Presentation changes do not enter edit undo history or project files.

The header selects Editor or Convert with a remembered workflow preference. Both use the same source library, while `useConversion` owns output-only settings, selection, and an independent batch queue. `conversionSettings` always creates a neutral recipe from the complete original asset, so conversion never applies or changes editor drafts. Automatic waveform analysis is enabled only in Editor. Conversion components separate the searchable/paginated source queue, shared encoding settings, import report, and results. Results persist across workflow navigation and retries; completed jobs are excluded from the next conversion until cleared.

`ImportReport` returns readable assets, per-file errors, and a skipped-file count. The library and project source count share a 2,000-file bound. Native folder traversal is recursive, bounded to 50,000 entries, and skips symbolic links; four probes run concurrently inside the native job coordinator. Browser directory selection and dropped file-system entries provide root-relative paths without uploading media. Dropped directory readers consume all paginated entry batches and use the same limits. Non-media files are filtered before probing. Engines retain partial successes when a source is corrupt or exceeds browser memory guards.

Bulk export passes explicit conversion/folder options to the engine. Native destination paths are derived from registered assets and a dialog-approved folder token, with validated path segments and rejection of symbolic-link subfolders. Successful temporary output is published with exclusive copying and numbered filename collisions, including when converting into the source folder. Browser results carry a relative path; `createDownloadArchive` streams their local Blob URLs into a self-contained ZIP using `fflate`, validates entry paths, and numbers collisions. ZIP creation is cancellable, lazily loaded, and uses no network service. Both raw result and archive URLs are released when replaced or cleared.

`InspectorTabs` separates the stable Effects catalogue and output settings. Panels stay mounted so searches and recipe state survive navigation. Applying registers an effect and reveals its timeline bar without opening settings. `EffectSettingsOverlay` renders one instance’s controls over the full visible height of the right island, tracks panel bounds with ResizeObserver and viewport events, and dismisses with Done, ×, Escape or an outside click. It is modeless so preview gestures remain available. The scrollable body keeps reset/removal actions accessible on small screens. Optional validated `addedEffects` membership keeps neutral effects (including volume/speed/transform and zero-length fades) attached through undo, project files and autosave; it does not add rendering filters. `effectAction` centralizes application/reset/removal. The first instance retains the legacy recipe fields; additional validated `effectInstances` own their parameters and IDs. `changeInstance` updates one target without erasing other instances or clip overrides. Repeated adjustments feed the same native/WASM filter planners and resource writers, with separate LUT and watermark paths and a combined ASS file with independent caption styles; speed products drive timeline/export timing. Caption and music owner helpers preserve per-instance settings through timeline edits, project portability and recovery. Timeline drops target the receiving clip; source effects retain their source scope. Trimming uses timeline handles and I/O shortcuts. Overlay preview players pause on dismissal. `ExportFooter` remains outside scrolling controls. Keyboard tab navigation uses arrow/Home/End keys and a single tab stop.

Timeline pointer gestures map against the full source track bounds, retain pointer capture while dragging, and clamp to the source duration. A transparent native range occupies the same track for keyboard and assistive technology; its focus indicator appears around the track. Section buttons still support keyboard selection. Removed gaps have no active section. `TimelineRange` captures resize gestures, renders transient local bounds, and commits once on pointer release. Cancellation discards the draft. `resizeSection` reconstructs retained cuts and split markers, bounding edges by adjacent sections without moving them. Caption ranges use source time; fade lanes map between source and output time through trims, cuts, and speed. Fade durations clamp when an edit shortens the output. Playback publishes media time and enforces retained sections on animation frames, while paused previews use media events.

## Project persistence

Version 1 `.frame.json` documents contain source metadata and edit recipes, without source paths, preview URLs, or embedded media. The parser validates structure, numeric limits, recipes, and bounded collections before restoring. Reopening matches source metadata against the library; missing or renamed sources can be imported and explicitly relinked. Restoring validates recipes against the actual sources again, then records the change in undo history. Project schemas are independent of engines; bump the version and provide explicit migrations when changing incompatible recipe fields.

Export presets store a validated output-only snapshot, separate from source trim, crop, and gain. Built-in presets are capability-filtered; custom presets use versioned, bounded local storage and can be replaced by name or deleted. Storage failure falls back to the session with a visible message.

Speed is recipe data, not an output preset. Source time remains the basis for cuts and playback; output duration divides retained source time by speed. Shared audio/video filters apply after retained sections are joined. Pitch preservation uses chained `atempo` stages; pitch shifting resamples at a changed rate. Version 1 projects without the new fields receive compatible defaults.

Audio/video fades operate on output time after cuts and speed. Preview maps the source playhead back to output time and updates gain/opacity using animation frames. Crossfades use normalized video time bases and audio formats, with validated overlap limits; composition duration subtracts the overlap at each boundary.

Audio cleanup filters run after speed processing and before final manual gain/fades. Loudness normalization explicitly negotiates channel layouts around resampling for compatibility with both native and WebAssembly FFmpeg. Preview generation chooses a bounded retained section and returns a temporary stereo WAV; source recipe changes revoke the preview.

## Composition

A composition is an ordered list of source assets and recipe snapshots. Its planner applies each source’s retained ranges, crop, and gain, normalizes frames and audio formats, and concatenates labeled streams. Missing video audio becomes a duration-matched silent stream. Source metadata and compatible first-source artwork can be retained. Native and browser engines use the same plan; source files remain immutable. Drag ordering has keyboard-accessible move buttons.

## Desktop boundary

`launchArguments` accepts supported local file arguments and an explicit Editor/Convert workflow, with `--` separating filenames from options. Electron’s single-instance lock routes later launches into the primary app; macOS `open-file` events enter the same bounded `LaunchInbox`. It groups same-workflow launches arriving less than 1.5 seconds apart, deduplicates pending paths, and preserves distinct selections in order. Group IDs survive consumption, allowing Explorer's separate per-file activations to remain one selection even while probing is underway. Conversion replaces the previous checked selection for a new group and accumulates files within the group; unrelated library files remain unchecked. Overflow produces a visible error without discarding previously queued selections. Window creation is guarded against native event reentrancy until the main window has been assigned.

The renderer subscribes to availability and pulls an opaque launch ID when its operation lock and dialogs permit importing. Only the main process retains selected OS paths. `desktop:import-launch` checks the caller, consumes the queued ID inside the native job coordinator, probes media, and reuses already imported sources. Workflow activation happens after acquiring the renderer lock, so automatic waveform analysis cannot race conversion imports. Requests arriving during exports remain queued, and renderer reloads can pull undelivered requests. The preload exposes no arbitrary-path import API. Reopening a registered file selects it without replacing its undo history or recipes.

Shell integration is separate from media processing: `shell-action-definitions` generates installer and file-manager resources, `shell-actions` installs/removes and checks per-user actions, `windows-shell-actions` manages owned classic Explorer registry keys, `windows-primary-menu` runs the native component manager, `windows-shell-integration` combines both Windows status results, and `system-integration` owns the app menu/CLI and trusted Settings IPC. Windows installer and runtime management share the same registrations and opt-out preference. Certificate approval is a separate trusted main-process operation: a native confirmation precedes UAC, the elevated helper can only trust/revoke its compile-time pinned public certificate in LocalMachine Trusted People, and package/menu registration remains in the original user account. Settings exposes certificate scope and removal; uninstall does not revoke shared machine trust. On x64 Windows 11, a sparse MSIX registers the small native `IExplorerCommand` extension alongside classic verbs. The native command validates the selection and launches Frame directly with bounded, quoted argument batches; the renderer never handles COM or registry paths. Development actions include the Electron executable and absolute app directory, while the desktop launcher prepares a built renderer for cold starts. Settings keeps unavailable web controls visible and disabled. Theme previews and settings UI are separate components; navigating Settings preserves editor drafts and conversion selections. The supported-extension JSON is shared with file import, keeping installed verbs and accepted types consistent.

The preload exposes only import, sample import, export, validated project saving, cancellation, release, and progress subscription. It does not expose Node.js or arbitrary IPC. File-drop paths are derived from real File objects in the isolated preload. Main-process requests are accepted only from the application's main frame; source paths are stored behind opaque IDs. The renderer cannot choose an arbitrary input or output path for FFmpeg.

Native tools run through `spawn` with arrays, never a shell. FFmpeg and yt-dlp are prepared from checksum-verified repository files, then packaged together outside ASAR. A shared resolver selects development or packaged tool paths. FFprobe remains a platform-specific npm package whose path is resolved outside ASAR. FFprobe discovers stream capabilities. Export destinations come from the native save dialog. Output is written beside the destination under a temporary filename and moved only after encoding succeeds; failed/cancelled jobs clean up that temporary file. The sample is an external resource because native subprocesses cannot read inside ASAR.

The window uses context isolation, renderer sandboxing, disabled Node integration, a content security policy, denied new windows/navigation, and denied browser permission requests. The preview protocol serves only registered assets.

## Audio analysis

Waveform generation uses FFmpeg `astats` and bounded peak windows across all channels. Both engines use the same arguments and peak-log collector, returning source-time peak data for an SVG timeline. Source waveform analysis uses its own cancellable background job coordinator, so it does not block editing or exports. Native FFmpeg processes report progress through the narrow bridge; the renderer never chooses input paths. Web analysis explicitly sets the information log level because a preceding FFprobe call changes shared logging state.


## Web boundary

The FFmpeg WebAssembly adapter and its worker load on first use. Core files are copied from the lockfile-installed package and hosted by the application. Files remain in a renderer-owned map; temporary worker filesystem files are removed after probing/export. Blob URLs are released when library items or export results are removed. Cancellation terminates the worker; a later job reloads the engine without losing imported source Files.

Core 0.12 returns `-1` when FFprobe returns normally without updating its exit sentinel. Imports accept that sentinel only with fresh JSON output and validated stream/duration data; FFprobe's explicit error section is rejected. This compatibility behavior is exercised by valid and corrupt browser imports.

## Extending

- **Output formats:** add a format descriptor in `src/core/formats.ts`, its type ID, and any necessary encoder options in the planner. Verify native and browser codec support with real output tests before advertising it.
- **Editing operations:** add serializable recipe data, validation/planning, and a focused control component. Engines stay unchanged when the operation maps to FFmpeg arguments.
- **Media kinds:** add the kind and metadata, supported import/probe handling, appropriate preview/control components, and capability-aware format filtering.
- **Alternative engines:** implement `MediaEngine` and select it in `src/engines/index.ts`. Platform-specific options should be represented by capabilities and only shown when supported.
- **Composition:** source-referenced audio layers and ordered clips already support mixing and sequencing. Keep new track types and timeline algebra independent of playback and UI rendering.

Files should remain focused on one responsibility. There is no untrusted plugin loader in this version; extension points are source-level modules.

Recipe resources (caption/text files, PNG overlays, cover artwork, chapter metadata and LUTs) use engine-generated temporary paths, with bundled DejaVu fonts or the selected installed desktop family, and are cleaned up after each operation. Browser analysis is a separate adapter. Native jobs latch cancellation across hardware detection and retries; only encoders that complete a real short encode are offered. Proxy files are served through opaque media URLs and never replace source paths in export planning. Workspace recovery automatically restores validated portable recipes and exact source-index links. Browser checkpoints atomically retain uploads in IndexedDB; desktop checkpoints keep original paths and persistent copies of downloaded media in the user-data directory. A serialized write queue protects clearing from older pending saves, and an unchanged partial recovery preserves the prior checkpoint. Portable project files remain independent of this local media cache.

Direct URL import shares HTTP/HTTPS validation, filename handling, streamed byte limits, progress, and abort logic across engines. Browser imports reuse ordinary file probing. Desktop streams through Electron’s network stack to private temporary directories, probes raw formats with network protocols disabled, and cleans up downloads on cancellation, removal and exit. URL import uses trusted IPC and the existing exclusive operation lock.

Desktop YouTube imports normalize an allowlist of individual video URLs and validate mode/quality in the main process. A pinned standalone yt-dlp includes the EJS solver; Electron's Node runtime runs the solver with yt-dlp's permission flags. No config, plugins, remote components, cookies, or self-update commands are enabled. Arguments are passed directly to spawn, output paths must resolve inside the owned temporary directory, and progress/errors are translated without exposing raw downloader output. Cancellation stops the entire process tree (process groups on POSIX; taskkill on Windows) before partial-download cleanup. Packaging verifies the official binary and notice checksums for the target platform, includes the tools outside ASAR, and rejects unsupported/cross-platform builds. Updating yt-dlp is an explicit source/build change.

## Review and delivery tools

Marker editing has been removed. `legacy-chapters` validates read-only points from old projects for chapter-export compatibility. Timeline snapping derives both source and output landmarks from clips, captions and audio tracks. View settings such as magnet state and playback loops stay outside recipes. Frame stepping and timecode navigation operate through the same source/output mapping used by preview and export.

Contact sheets and scene detection use pure argument planners; their adapters only manage native processes or WASM files and translate progress/results. Scene results are reviewable before applying a single undoable split patch. Loudness analysis appends EBU R128 measurement to the actual edited audio export graph, so source gain, ordered effects, cuts, speed, fades and audio mixing use the same processing.

Audio output rate, channel override and WAV precision, plus GIF loop/palette/dithering options, are validated output settings shared with projects and presets. Filename templates are expanded from registered asset metadata, never evaluated as shell expressions. Stable batch numbering survives retries, and exclusive publication prevents overwriting originals or completed exports.

## Audio layers

Each recipe can reference up to 16 imported music/voiceover sources. Layers store portable source identity, output-time placement, a source excerpt, independent gain/fades, mute and repeat. Engines resolve identities only against their registered library and generate their own input paths. Projects validate that every layer source is represented and relinking rewrites layer identities to the chosen media.

The planner processes the original track and additional sources separately, aligns layers using delay/padding, then mixes with optional peak limiting after channel conversion. Global output fades apply once to the final mix; local clip and layer fades remain independent. Merge composition embeds the same mixer for each source recipe before concatenation or crossfade. Conversion-only recipes have no audio layers.

Live playback synchronizes hidden audio elements with output time and approximates source levels; processed mix previews and loudness analysis render the exact graph. A single background waveform queue serves main and additional tracks, respects the automatic-analysis preference, caches source peaks, and displays excerpt/repeat/fade/gain changes without rereading files.

## Desktop watch folders and completion notices

Watch-folder configuration uses trusted main-process IPC and native folder selection. The runner polls bounded, link-free directory collections, waits for unchanged size/mtime across scans, interleaves multiple watches, and processes one native conversion at a time independently of renderer operations. Native folder selections are approved for the originating window and consumed when a watch is added. Source/output paths may not overlap across any watches, including paused watches, which prevents conversion loops. Per-file failures are suppressed until the file changes or the user explicitly retries; successful fingerprints persist atomically across restarts. Shutdown cancels active work and briefly drains pending completion records.

Completion notifications are an independent desktop capability with a durable user preference. Saved exports, merges and batches notify only while their originating window is in the background; partial failures remain explicit and cancellations stay quiet. Notification failure never turns a saved export into an error.

Desktop export history records successfully published outputs centrally, independently of renderer windows. Mutations serialize to an atomic per-user JSON file; trusted IPC exposes bounded history and reveal-by-entry-ID. Shutdown waits briefly for watch jobs and history writes to settle.

Imported sources have a SHA-256 fingerprint sampled from their first and last 64 KiB plus size, with the same algorithm on web and desktop. This is an identity aid, not a full-file integrity guarantee. Projects retain it for same-name relinking; audio layers use runtime IDs in memory and source indices in portable projects. Legacy projects still match using their available metadata.

Automatic music ducking separates foreground source audio and voiceover tracks from music. The sidechain detector uses aligned 1,024-sample blocks with padded tail audio to preserve the complete music output. Live HTML playback approximates levels; processed preview and export render ducking exactly.

Chapter metadata is generated from output-mapped markers and written as a temporary FFmetadata input. Merge chapters share the composition transition mapping. Explicit output metadata uses validated fields and argument arrays; custom covers are bounded PNG resources stored in individual projects, excluded from reusable format presets.

Batch CSV reports use the actual retained job results, with quoted cells and spreadsheet formula protection for user text. Disabling autosave stops new snapshots and page-hide writes while keeping the last saved workspace for automatic reopening. Clear library removes both the checkpoint and retained media.

Command search uses a core text-ranking function and a focused modal component. Action labels outrank incidental matches in help text; disabled results explain their prerequisites and never execute on Enter. The command controller uses the existing editor/project actions, coordinates with other dialogs and desktop launch delivery, and opens controlled inspector tabs without changing recipe scope.

Project serialization checks UTF-8 bytes per source before joining embedded resources, rejects documents above the importer’s 16 MB limit, and falls back to compact JSON when indentation alone would exceed it. Autosave captures recipe references while editing and serializes after its debounce or page-hide event.

Caption effects keep a single cue per instance; `individualCaptionEffects` upgrades legacy arrays during project parsing, while imports append effects in one undoable edit. The first cue retains the legacy fields for compatibility. Captions have a separate 1,000-cue budget so a subtitle import leaves room for other effects. `caption-style` validates portable styling and installed family names. `font-names` reads SFNT/TTC name tables, `installed-fonts` scans standard OS/user font directories with bounded reads, and a trusted IPC returns family names only. The native resource writer resolves selected names from this inventory and copies font files to its temporary directory. Browser resources fetch only needed bundled variants and report desktop fonts before processing. ASS styling uses safe generated fields; font paths never come from project data.

`FrameObject` shares preview selection, inline text editing, proportional corner resizing and one-commit pointer gestures between captions and watermark objects. Cancellation restores the original value; adapters translate frame geometry into each recipe type. `FontPicker` provides an editable accessible combobox backed by bundled and installed-font options. `TransientMessage` owns the five-second visibility timer and background countdown; a stable text key prevents playback rerenders from restarting it, while explicit message versions restart identical repeated notices. Completed browser downloads remain separate from transient notices.

The catalogue declares repeatability centrally: only captions and watermarks create new effect instances. `existingEffectTarget` resolves the selected clip/source (including legacy stacks); all add entry points reopen existing singleton adjustments, and the core action also rejects duplicate additions. Older saved stacks remain parsed and processed without losing settings.

Watermark recipes optionally store source-time ranges; missing ranges retain the legacy full-source behavior. `WatermarkLanes` maps ranges into ordered clip fragments, and timeline gestures update one owner in one undo step. `overlayIntervals` uses the same cuts/order/speed mapping as captions. Text resources use timed ASS events, artwork filters use output-time enable expressions, and frame preview passes the complete timing context while applying local visual settings. Mixer tracks keep independent output-time placement. Main clips, timed effects and audio excerpts preserve usable handle widths regardless of precise duration; snap targets exclude both boundaries of the dragged item so short ranges can expand with small gestures.
